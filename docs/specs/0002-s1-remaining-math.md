# 方案：S1 其余确定性数学

> 状态：**完成（2026-10-18）**。用户批准继续实施后，执行 A–E，S1 默认检查 427 项通过。证据见 `../verification/s1-math.md`。
>
> 最初草稿按“乘法最后由人接入”设计；实际实施前用户已先完成 `Fixed64.Mul`，197 个乘法测试和全量 373 个测试通过。因此未新增乘法依赖排除，所有向量测试直接进入默认验收。

## 目标

补齐除法、平方根、三维向量、确定性随机数、正弦与余弦查找表，使 S2 能直接使用统一的确定性数学 API。

本次交付的 done-when：所有新数学功能通过边界测试、百万组参考比对、反向探针和 V3；向量和乘法均直接纳入默认检查；`.ai/verify.sh` 退出 0，测试总数与精度有记录。实际结果为 427 项全绿，无分类排除。

**S1 已完成。** 这不代表 S2 游戏模拟、S3 回滚或 V6 跨运行时确定性已完成。

## 不做

- 不实现、替换或绕过 `Fixed64.Mul`；保留现有 `operator *` 到 `Mul` 的调用。
- 不实现回滚调度、游戏状态、碰撞、Unity 表现或网络。
- 不增加通用 128 位数值库、矩阵、四元数、反三角函数、幂或对数。
- 不新增生产依赖，不修改确定性守卫的规则表。
- 不提交、推送、切换分支；不把 .NET 检查当成 Unity 或跨运行时验收。

### 参考与采用方式

- [FixedMath.NET 的 Fix64](https://github.com/asik/FixedMath.Net/blob/master/src/Fix64.cs)：参考整数除法、逐位平方根以及正弦 LUT 加插值的思路。舍入、饱和和误差以本项目契约为准，不把另一库当成唯一正确性判据，也不直接复制其整个实现。
- [Sebastiano Vigna 的 SplitMix64 原始实现](https://prng.di.unimi.it/splitmix64.c)：采用明确的 64 位状态转移和输出混合，保留来源与许可说明；测试的黄金序列从独立参考取得。

## 设计

### 1. 标量 API 与数值契约

在 `Fixed64` 增加 `Div(a, b)`、`operator /`、`Sqrt(value)`，以及向量使用的 `Abs`、`Min`、`Max`。不顺带扩展类型转换和整数取整 API。

| 操作 | 契约 | 实现边界 |
| --- | --- | --- |
| `Div` | 精确 raw 商为 `(a.RawValue * 2^32) / b.RawValue`；最近舍入，恰好一半远离零，最后饱和 | 按无符号幅值做逐位除法，保留商与余数；处理 `long.MinValue` 的幅值与商进位，不能先在 long 里左移分子 |
| 除零 | 所有分子（含 0）均抛 `DivideByZeroException` | 不把无定义运算伪装成饱和值 |
| `Sqrt` | 非负输入返回最接近 `sqrt(raw * 2^32)` 的 raw 整数；负数抛 `ArgumentOutOfRangeException` | 逐两位整数开方；不调用 `Mul` 或浮点；参考实际使用独立 BigInteger Newton 整数根 |
| `Abs` | `Abs(MinValue) == MaxValue` | 与既有饱和取负一致 |
| `Min` / `Max` | 直接按 raw 比较 | 不引入新舍入 |

所有中间移位、乘加的位宽与合法范围在实现旁说明。生产代码不使用 BigInteger、Int128 或 UInt128。

### 2. `FixVector3`

新增只含三个 `Fixed64` 字段 `X/Y/Z` 的 `readonly struct`：构造、`Zero`、`UnitX/Y/Z`、相等、加减、取负、标量乘除、`Dot`、`LengthSquared`、`Length`、`Normalized`。

- 每个分量的算术复用 `Fixed64`，不另写乘法内核；点积按 X、Y、Z 顺序逐项乘、逐项饱和相加。明确它不承诺无限精度累加后只饱和一次。
- `LengthSquared` 采用上述点积语义，可能饱和；不能据此计算大向量的 `Length`。
- `Length` 和 `Normalized` 先用最大分量幅值缩放，再求平方和与平方根，避免原始分量自乘过早饱和；最终长度超范围时饱和。`MinValue` 的幅值处理必须单独覆盖。
- 零向量归一化返回零；非零向量必须先缩放，不能因微小分量平方被舍入成零而丢失方向。
- 精度契约覆盖全部可表示分量。设 `u = 2^-32`，理想长度 `L` 为精确欧氏长度夹到可表示正范围，则 `abs(Length - L) <= 16*u*max(1,L)`；非零向量的每个归一化分量与理想单位向量之差不超过 `16*u`。长度的相对容差用于容纳缩放后平方根量化的放大，不能要求任意大向量都只有一个 raw 的误差。
- 独立参考用 BigInteger 对原始分量精确平方、相加，再用高精度整数开方构造长度和归一化参考区间；不能复用生产缩放流程。加减、标量乘除和点积仍按逐步标量舍入、饱和的精确 raw 参考验收，不使用上述近似容差。
- E 阶段对百万组向量验证误差界，另测零、单个正负轴、3-4-5、最小 raw 分量、量级悬殊、`(1e9,1e9,0)`、含 `MinValue/MaxValue` 的组合和长度刚好饱和的边界。参考自身先以手算向量验证，误差界在实现后必须测得，不能把设计目标当作实测结果。
- 测试覆盖构造、相等、加减、除法、乘法、点积、长度与归一化；由于乘法已接入，不使用 `RequiresFixed64Mul` 或其他分类排除。
- 不采用测试替身、临时乘法或测试参考实现注入生产路径。依赖测试在用户完成乘法后直接验收原生产路径。

### 3. `DeterministicRandom`

新增可复制的值类型，只保存一个 `ulong` 状态：构造参数为 seed，公开当前 `State` 的只读值，通过构造参数可恢复状态；提供 `NextUInt64()`、`NextInt(int exclusiveMax)`。

- SplitMix64 的溢出明确使用 `unchecked`；seed 为 0 和默认结构体均有效。
- `NextInt` 接受正上界，用拒绝采样消除直接取模的偏差；非法上界抛异常，且不推进状态。
- 无共享可变静态状态。复制随机数结构体即复制序列位置；调用处将来必须把它作为模拟状态保存。
- 测试黄金输出、状态推进、结构体复制后独立演进、恢复后逐项一致，以及拒绝采样确实拒绝低端区间的定向种子。
- 测试生成器保持独立，不改成调用生产随机数，否则相同错误可能污染输入和被测对象。

### 4. `FixMath` 的三角函数

新增 `FixMath.Sin(Fixed64 radians)`、`Cos(Fixed64 radians)` 与 `Pi`、`TwoPi`、`HalfPi` 常量。角度采用弧度，常量各自按最近值量化。

- 离线生成覆盖一周的 4096 个等间隔区间与闭合端点，以 raw long 字面量固化；运行时仅查表与整数线性插值。
- 表为私有静态数组，不向调用方暴露可写引用；初始化不读文件或生成浮点数据。
- `tools/generate_trig_table.py` 使用 Python 标准库 Decimal 高精度计算，固定精度、舍入、换行和输出格式，保留完整来源与再生成命令。`--check` 只比较，不写回文件。
- 先对 raw 角度按 `TwoPi.RawValue` 取模，再算索引与插值余数；余弦在归一化索引上平移四分之一周，不对原始角度做可能饱和的加法。
- 插值直接做有界的整数加乘除，不调用未实现的 `Fixed64.Mul`；必须给出中间结果不会超过 long 范围的推导。
- 任意 raw 输入均应有确定、无异常的输出，范围为 `[-One, One]`。与真实正余弦比较的精度承诺限于 `[-1024, 1024]` 弧度，绝对误差不超过 `1e-6`；测试覆盖基本周期密集采样、负角度、周期接缝及范围内百万组角度。
- 全 raw 范围按量化后的周期取模，不承诺相同的真实角度误差界；最大角度可能累积周期量化误差。S2 应保持朝向角周期归一化。单位圆关系只用于辅助检查，独立精度判据是测试侧 `System.Math.Sin/Cos`。

### 5. 验证与乘法接入

- 增加独立的除法、平方根 BigInteger 参考、手算边界值及测试生成器覆盖统计；各跑百万组。除法覆盖两侧饱和、非饱和正负结果、精确值、半途舍入及临界余数；平方根覆盖 0、最小正值、完全平方邻域、最大输入。
- 三角表检查再生成一致性，同时以不同计算方法的测试参考验证精度，不能只把表与自身比较。
- `.ai/verify.sh` 无分类排除；增加只读的表生成一致性检查，报告完整测试总数。
- 不给 AI 完成的独立功能标 `HumanTodo`，不跳过其失败。
- 反向探针分别破坏除法舍入、平方根最后一位、随机状态推进与拒绝路径、查表索引与表项、向量长度/归一化/点积，确认对应检查失败后恢复。每次探针恢复后重新构建，以源文件内容一致和最终差异为准。全部 9 项实际执行，证据已记录。
- 用户 `Mul` 已通过，删除其 `HumanTodo` 和脚本中的整个分类过滤；完整重跑后宣布 S1 完成。新增 `docs/math-contracts.md` 列明精度、运算顺序和饱和边界。
- 不改变 `AGENTS.md` 等文件中的工程约束；仅同步命令状态与交接链接。总方案的进展记录如实区分人写乘法与 AI 实现其余数学，不把 .NET 验收扩大为 V6 验收。

**考虑过但没选的方案**：整体引入数学库会违反生产无 NuGet 约束，也会带入不同的数值语义；先写临时乘法会破坏人先实现的对照实验；运行时生成 LUT 会将平台浮点差异带入模拟；仅以 `sqrt(Dot(v,v))` 计算长度会让大向量过早饱和。

## 质疑

- **原先最弱假设：先交付依赖未完成乘法的向量。** 用户先完成乘法后，已能直接做全量集成验收，此风险已解除；静态审查仍不代替动态测试。
- **饱和运算不满足通常的向量代数。** 点积相消可能因中间饱和失真。此版本选择明确顺序并限定游戏坐标范围；若 S2 需要对极大向量做精确相消，应另提累加器设计，不能偷偷改变语义。
- **随机数测试只验“同种子相同”不够。** 两个实例都返回同一常量也会绿；必须有外部黄金序列、状态值和拒绝路径判据。
- **三角常量量化使周期关系不精确。** 不要求三个独立量化常量在 raw 上严格互为倍数，基点给出几个 ulp 的容差；精度承诺不扩展到巨大角度。若需求是全范围 `1e-6`，需要高精度范围约简，重新审批设计。
- **百万组全是饱和也可能绿。** 每类参考比对都要统计真正非饱和、舍入和边界路径的数量；不能只报总组数。
- **快速检查可能超预算。** 先实测耗时；如超过总方案的一分钟预算，提出“快速子集 + 完整 V1”的命令与 CI 分工，再决定调整，不静默减少覆盖。
- **廉价假设检查**：2026-10-17 以 4096 区间的线性插值误差上界 `h²/8` 加量化裕量估算，`[-1024,1024]` 上约 `3.33e-7`，低于 `1e-6`。这是选表大小的估算，尚非实现精度证明。
- **回退方式**：各模块仅做增量添加；若某阶段失败，停止该阶段，保留已验证部分与现有 `Mul` 占位。删除本会话新增代码前核实是否已有用户后续修改，不用 Git reset 或覆盖用户文件。
