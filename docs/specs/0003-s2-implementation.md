# S2 无头模拟实施

> 状态：完成（2026-10-18）。用户要求 S1 提交推送后进入下一阶段，并指定 `docs/s2-gameplay-spec` 分支上的定稿玩法规格；本轮按该规格实施，不重新决定玩法。最终 `.ai/verify.sh` 629 项通过，退出 0，0 警告/错误。

## 目标与边界

权威规则为 `0002-gameplay.md`（原文来自 `docs/s2-gameplay-spec` 的 `c384874`，仅增加当前分支尚不存在的文件，没有覆盖任何现有文件）。总方案 S2 done-when：V2 重复回放逐帧校验和一致，场景测试通过，无头机器人能打完一场。

只做 S2：固定帧输入、移动/跳跃/冲刺/攻击/击退/身体互推、回合、值快照、稳定校验和、输入回放和无头 CLI。不做 Unity、传输、预测或回滚调度；用户的 `Fixed64.Mul` 保持不变。

## 实现选择

- `GameState` 含两个 `PlayerState` 值字段及全局帧、阶段和比分，不用托管数组或引用字段。`GameSnapshot` 保存整个状态值；新增值字段自然参与快照复制。
- `ArenaGame.Step(ref state, inputs)` 是唯一模拟推进入口。两名玩家各自基于开始状态推进，再身体互推，计算双方命中布尔值后统一应用，最后推进回合。没有现存调用方；新调用方为场景测试、回放验证和 headless。
- 输入是两个 byte 的 `FrameInputs`；方向/动作由规格解释，保留位必须为 0。前帧有效输入属于玩家状态，不做缓冲。
- 所有速度/判定常量直接由精确二进制分数构造；8 方向使用规格给出的 `SqrtHalf` raw。受击次数用 int 表示，不人为封顶；可达状态受 3600 帧回合限制。
- 校验和明确按字段顺序用 little-endian 字节计算 FNV-1a 64，不散列结构体 padding，不调用运行时 `GetHashCode`。独立字段覆盖测试必须证明任何状态字段改变都会被检查到。
- headless 是 net9.0 工具，只引用 `Arena.Sim`，负责文件、命令行、机器人和 CSV；这些 I/O 不能回流纯模拟程序集。回放以逐帧两玩家按住输入字节表示。

## 质疑

- 规格表给出了明确数值，其“第 6 次命中一定出界”的动机说明并非任意位置/朝向的几何保证；实现遵循 `(2+h)/16` 的速度和出界判据，不增加命中次数强制判负。
- 同帧互中最容易因先修改一方而丢失另一方的命中；必须在写回硬直前取得两边结果。
- 快照全值复制不自动证明校验和字段齐全；反射驱动的叶字段覆盖检查作为独立判据。
- 完全镜像机器人可能无限平局；双方策略使用不同的确定性攻击节奏。完成判据还要求实际发生受击，不能靠只走下平台冒充战斗演示。
- V2 和 headless 证明当前 .NET 运行时行为，Unity/IL2CPP/WebGL 的 V6 仍在后续阶段。
